# 4.2 → 4.3 Proto 混淆名映射表

> 背景：4.3 客户端 proto 相比 4.2 对字段 tag 做了整体重排，并重新生成了一批混淆字段名。
> 本表记录 GameServer 中各模块从 4.2 迁移到 4.3 时实际发生的字段/类型/枚举重命名。
>
> 原则（与 issue 讨论一致）：
> - **可读名 (✅)**：4.3 生成的 proto 属性本身就是可读名 —— 代码中**已全部使用可读名**，无需替换。
> - **已恢复 (♻️)**：该字段在 4.2 曾是可读名、4.3 dump 时被混淆。已执行「方案 A」：在生成的 `.cs`
>   与 `Proto/ProtoFile/*.proto` 中把字段/类型**改回 4.2 的可读名**（tag 编号不变，wire 完全兼容，
>   已通过运行时 round-trip 验证）。
> - **仍混淆 (🔒)**：该字段在 4.2 与 4.3 **均为混淆名**（语义未知），无可恢复的可读名，按新名称使用。
> - **不确定 (⚠️)**：多个同类型字段无法靠 tag/类型区分，按命名一致性或 tag 顺序尽力对应，详见备注。

> **方案 A 已执行**：以下 7 处已改回可读名（生成 `.cs` + `.proto` 同步，运行时已验证）：
> `SellItemCsReq.to_material`、`LockEquipmentCsReq.equipment_id_list`、
> `DiscardRelicCsReq/ScRsp.discarded`、`GetFriendLoginInfoScRsp.friend_uid_list`、
> `GetJukeboxDataScRsp.unlocked_music_list`、消息类型 `LHHGCDLCJDA → MusicData`、`MusicData.is_played`。
> 其余 🔒 项 4.2 即为混淆名，无法恢复，保持新名。

## 三、说明

- 上表中 **✅ 可读名共 ~19 处**，代码均已使用可读名，无需任何替换。
- **🔒 仍混淆**的字段，4.3 生成的 proto 属性只有混淆名，C# 调用侧没有可读别名可用；
  若要彻底"可读化"，唯一途径是修改 `Proto/ProtoFile/*.proto` 字段名并重新生成 `Proto` 工程
  —— 但这些字段之所以混淆，正是因为 dump 时未能解析其真实语义，盲目改名有误导风险，故保持现状。
- 各调用点已在代码内就近加了 `// 4.3: 旧名 -> 新名` 注释，便于日后比对本表。

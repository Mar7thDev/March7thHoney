# 登录与场景回归

[English](login-scene-regression.md) | 简体中文

`LoginSceneRegression` 通过内存 KCP 连接驱动真实的请求处理器，检查登录、RSA、场景加载、传送，以及运行在场景之上的大部分玩法：任务、角色、模拟宇宙、挑战和活动。修改登录、场景、任务、队伍、角色或下文列出的任一功能后运行。

项目：[`scripts/LoginSceneRegression/`](../../scripts/LoginSceneRegression/)

## 运行方式

从仓库根目录执行：

```powershell
dotnet run --project scripts/LoginSceneRegression/LoginSceneRegression.csproj -c Release
```

选项：

- `--legacy-cache <升级前的 Resource.bin>`：额外验证升级前缓存的反序列化和过期检查。
- `--resource-cache <新生成的 Resource.bin>`：使用从原始资源重新生成的缓存代替 `Config/Resource.bin`，例如在替换该文件之前。缓存只复制到临时目录，不改写源文件。

## 前提条件

- 回归使用随机 RSA 密钥、临时 SQLite 数据库和仅监听本机的 HTTP 服务，不读取运营配置、不连接生产服务器，也不改写现有数据库。
- 场景测试读取当前 `Config/Resource.bin` 的副本，不重新生成缓存。
- 角色试用用例需要带 `AvatarDemoConfig.StageType`/`SPList` 的缓存。缓存缺少这两个字段时，测试在角色试用部分明确报错停止。
- 测试结束时会输出临时产物的路径。

## 覆盖范围

大部分检查位于 `scripts/LoginSceneRegression/Program.cs`。`MainFixRegression.cs` 包含模拟宇宙通用查询、小游戏数据处理器、队伍槽位与收藏、开拓者当前命途、遗器预设、副本/Raid 退出和头像框展示开关的检查；其他较大的部分各有独立文件，见下文。它们都由同一入口运行，使用临时 SQLite 数据库和内存 KCP，不接触真实玩家数据库。

### 登录与 RSA

- Shield 以及新版和旧版 Passport：三种 RSA 填充、1024/2048 位密钥、密钥不匹配、缺失或无效私钥、畸形密文、严格 UTF-8 和明文兼容。
- 解密失败必须在登录和自动注册之前返回错误。同一账号多次随机填充加密只能得到一个账号。

### 协议细节

- 数值标签：`SceneMapInfo.floor_id=14`、`retcode=6`。失败返回码独立编码；强制字段映射优先于旧版本推断；同时合并原始名与语义名作用域。
- `CommonRogueQueryScRsp`：查询类型即 `CCKJAEDDDCL` oneof 分支的字段号，按当前生成的协议代码读取。功能解锁分支 `CCKJAEDDDCL.BBEKBJPHEJKFieldNumber` 在 4.5 为 `15`、4.6 为 `1`、4.7 为 `10`、4.8 为 `15`。只有该分支带解锁集合，保持请求顺序与重复项；其余三类查询保持无分支，不臆造状态。
- `SocialPlayGetDataCsReq`、`PetMarbleGetDataCsReq`、`PetMarbleGetCycleTrialPetsCsReq` 有处理器，经源生成的 opcode 表注册。回包中所有单值子消息（递归 5 层，oneof 与列表除外）都以空消息下发，而不是未处理请求的空包体，避免客户端收到 null。补齐时不选择 oneof、不添加列表项。

### 场景加载与楼层状态

- 楼层存档条件：AND/OR/NOT 真值表、各比较运算符，以及缓存省略比较符时的等于语义。
- 恢复活动楼层变量置 `1` 的规则：有关联活动任务的 Town/Maze 楼层，资源默认为 `0` 的变量统一补为 `1`（`*_IsHidden` 除外）；显式存档值仍然优先；不写入玩家存档。启用任务系统时，`SceneStateByMainMission`/`WorldStateByMainMission` 不再补 `1`，保留资源默认值（官服对 `20001001` 下发 `0`），由剧情写入的存档值决定；未启用任务系统时仍补 `1`。在长乐天 `10202001/170`（虚构叙事入口）和流梦礁 `10304001/145`（末日幻影入口）上验证实际实体创建、传送下发、登录恢复、重复同步和存档覆盖，而不只是判断组开关。
- 地图组回包（对照官服 4.6）：楼层 `10001001` 的客户端 NPC 组 `4` 与自动任务触发组 `5` 即使没有服务端实体，也按任务条件进入 `maze_group_list`。`client_group_mission_info` 与同楼层的场景任务状态同步：前置主任务 `1000300` 已完成、`1000301` 进行中时字段可见，`1000302` 完成后组 `5` 卸载。当前及非当前楼层都检查客户端任务状态；当前楼层保留延迟卸载期间已加载的组；不改真实玩家存档。
- 任务状态列表按客户端组的加载/卸载条件与关联任务推导。楼层 `10001001` 与官服 4.6 入场快照的 32 个子任务逐项一致；进行中的剧情对话 `100030103` 不再进入入场快照，只经任务同步流下发。该推导在其余已抓包楼层的子任务集合上也逐项吻合。
- 精确排除仙舟异常道具：保留星槎海中枢 `10201001/280/300001` 与长乐天 `10202001/208/300001` 两项 `PCOnly` 抓包排除，并恢复旧安卓修复中的 `10202001/144/300003`、`10202001/208/300002` 排除。初始加载、直接创建和强制加载遵循同一规则；长乐天空组 `208`、星槎海中枢空组 `280` 不重复加载。
- 只排除长乐天 `10202001/169` 异常氛围组，并在同步时移除残留的组和实体；不依据 `IsHoyoGroup` 与 `Atmosphere` 的组合做全局排除。普通非初始道具、NPC、其他氛围组和储物舱段组 `8` 的电梯继续可用。活动楼层全开规则保持不变；传送、登录恢复和重复同步不会重新下发异常内容。兼容名单使用缓存中的楼层/组/实例，当前缓存无需重建。
- 登录恢复场景和传送场景都带有 4.5 初始化值。内存 KCP 两端验证 `1491 → EnterSceneByServerScNotify → EnterSceneScRsp` 的顺序；同地图移动、静默构建、无效传送和登录快照不会误发场景切换边界。

### 传送、副本与临时场景

- 传送成功与跨地图标志分别返回。无效入口、缺楼层/锚点/地图以及递归加载中止不再报告成功。同地图传送、重载和传送到剧情线保存的位置保持可用。
- 缺少资源配置或运行记录的副本退出不会抛异常或无响应：优先返回原入口；无效入口或指向副本的旧返回点改用默认出生点。登录时在加载场景前修复孤立的副本位置，保留正常运行和剧情线占用的位置。重置通知保留空物品列表，重复退出只应答。
- 临时场景（Raid）：存档中进行中的 Raid 已不在当前 `RaidConfig` 中时，重新登录会放弃该运行、删除记录并回到进入点（`OldEntryId`/`OldPos`）；离开该 Raid 同样回到进入点并删除记录。运行记录丢失时，离开回到默认出生点 `2000101`。`RaidConfig` 中存在的 Raid 默认仍在登录时恢复。重置用的 `RaidInfoNotify` 保留空 `item_list`。
- `ServerOption.ResetLocationOnLogin`（默认 `false`，可在后台设置页修改）：开启后，每次登录放弃进行中的 Raid（删除记录）以及挑战和星启（ChallengeTierce）运行，并在加载场景前把位置重置到默认出生点 `2000101`。剧情线进行中时不生效。

### 场景实体与进入战斗

- 召唤体领域 buff（`20001001` 的真实怪物；昔涟 `141501` → 召唤体 `14151` → 敌人 `141502`）：召唤体投放的 buff 以召唤体自身实体 ID 作为 `BuffSummonEntityId`，保留资源时长 `500`，每个敌人是独立的 buff 实例，离场刷新为 `1`。由有限时长 maze buff 的 modifier 创建的召唤体下发 `LifeTimeMs=-1`，随该 buff 移除而销毁，并带走投放的 buff；owning buff 为永久时仍以 45 秒兜底。`RemoveMazeBuffOnDestroy=false` 的召唤体（`14101`）销毁后保留已投放的 buff。
- 收容舱段斜坡怪物袭击，使用真实楼层 `20002001`、组 `5`、实例 `200007` 与内存 KCP 请求处理器：无命中目标的投射物（官服 4.6 seq 9469-9471）只返回 ACK，不创建战斗，也不清理场景召唤物。攻击来源始终取 `attacked_by_entity_id`，不会因 `cast_entity_id` 恰好等于角色实体 ID 而变成玩家攻击。还覆盖无效来源与目标、玩家正常攻击、怪物实际命中玩家时的遇袭 buff 与怪物 ID、重复请求复用战斗，以及缺少怪物 ability 的兼容路径。
- `/spawn`：参数解析（`lv`/`hp`/`s`/`x`/`r`；以 `/`、`|`、`\` 分波，每波 5 只自动分波；无效 ID 汇总报告）与 ID 解析（`monster`、NPC 怪物、经模板映射的战斗 MonsterID、物件、纯战斗怪物）。长乐天没有怪物配置时报告无模板。在资源中首个含可用怪物组的 Maze 楼层上，生成的怪物借用已加载组的组/实例/EventID，带偏移半径且旋转为零。战斗中自定义波次替换关卡波次（波次号 1..N、固定关卡、等级与血量覆盖）；只覆盖血量时保留关卡波次。混入真实怪物的战斗仍计入任务。生成的物件为 Open 状态，不带模板的事件/宝箱/交互，状态不写入存档。无效 ID、不存在的关卡、实体上限、缺少 ID 以及模拟宇宙场景都不会生成实体。

### 角色

- 角色装扮，使用真实的换装/脱下请求：换装本身把玩家标记为待保存，先下发保留等级、光锥和遗器的角色同步，再返回结果。拒绝不存在的角色、未知/未拥有或属于其他角色的装扮；重复换装只应答；恢复默认装扮不依赖皮肤解锁字典。使用实际库存物品验证装备归属和战斗序列化；从 SQLite 读回角色数据并重新登录后，过图与重登都保持选定的装扮和装备。
- 重复的基础角色记录：旧存档可能包含同一基础角色的多条记录（实际日志中的昔涟 `1415` 有一条已培养记录和五条空记录）。登录快照按基础角色 ID 保留首条记录，即服务端 `GetFormalAvatar` 选择的同一条，避免后面的空记录覆盖装扮、等级和装备。原始存档记录不删除也不合并，无需迁移、替换缓存或重建账号。新增角色或重复解锁命途不再追加相同的基础角色，也不重置已保存的命途数据。
- 缓存包含星神★阿哈时，`/giveall skin` 会发放 Star Lotto（`1151101`），重复执行只保留一份解锁记录。发放后服务端接受换装请求，从 SQLite 读回解锁数据并重登后仍能同步该皮肤。
- 角色快速升级，经源生成 opcode 表、请求解析和内存 KCP 验证。官服 4.6 抓包 seq `36813-36829` 与 dumper 的 `cmdid-registry.txt` 确认请求命令枚举 `KELLLHMHFHL` 对应消息 `EKLIDIDKFHC`（cmd 376），响应枚举 `MILFFHPMLMN` 对应 `PMEMIDKDAFG`（cmd 357）。4.7 分别为 cmd 355/341，4.8 为 332/395，直接使用已生成的同身份消息及其当前字段号。请求中 `IGOOJKMPMDC`、`KLMIBJIKIBB` 分别为目标等级和目标突破阶，`BACAOLDADMC` 为经验书费用，`OAINNDAHIMG` 为单独的突破费用。
  - 覆盖：已突破角色使用 8/6/7 本经验书升到 30 级；20 级未突破角色一次请求同时支付经验书和资源表中的突破费用，升到 30 级/1 阶；返还 2 本物品 211（角色经验书）；角色已有经验参与退款计算。
  - 服务端先校验全部费用、库存、等级上限以及开拓等级/均衡等级要求；成功后先同步角色、信用点和最终材料余额，再应答。
  - 失败路径：缺角色；缺信用点、经验书或突破材料；少报突破费用；重复材料行；数量溢出；用光锥或光锥经验材料代替角色经验书；经验不足；非法目标。重复或并发的相同请求只扣费一次。
- 光锥快速升级：真实 `EquipmentQuickUpCsReq` 处理器通过内存 KCP 校验当前命令（4.7 为 513/517，4.8 为 548/529）和字段身份。覆盖日志中的五星光锥 1→20（5 个 223 材料）；8 个 221 + 10 个 222 + 五件三星狗粮的混合消耗；以及官服 4.6 seq `36859` 的四星光锥 20→30 / 突破 1。信用点、突破材料、经验返还、删除狗粮通知和目标光锥同步都在响应之前到达。还检查受保护或已装备的狗粮、目标自身、重复或缺失的唯一 ID、非法或溢出数量、错误材料、经验/库存/信用点不足、突破费用及均衡等级限制、仅突破时保留原经验，以及重复和并发请求只扣费一次。所有失败都保持玩家状态不变。
- 开拓者命途：资源中开拓者命途按奇数男 / 偶数女配对。存档保留两种性别的命途，但 `GetAvatarDataScRsp` 与 `PlayerSyncScNotify` 中的命途列表和 `BasicTypeIdList` 只下发当前性别。切换命途时按性别归一并返回实际存储的 id；其他角色的命途不能套到开拓者上；`/hero type` 拒绝非开拓者命途；切换性别后保留原存档命途。
- 开拓者当前命途修复：在任务开关覆盖生效之后执行，不会提前替尚未选择性别的剧情新号决定性别。女性存档上的男性当前命途改为对应的女性命途；非命途 id 回落到已拥有的同性别命途，且 `GetAvatarDataScRsp` 的命途列表包含该命途。同时修复缺失的当前命途数据和陈旧的 `CurBasicType`；修复是幂等的，正常数据保持不变。
- `/giveall avatar`：不带参数时，已拥有角色的等级、星魂和当前命途保持不变，新角色为 1 级 / 0 魂。显式 `r` 写入角色已拥有的全部命途且不改等级；显式 `l` 不改星魂。开拓者只解锁当前性别的命途。
- 遗器预设：新建需要已拥有的角色和已拥有的遗器。拒绝未知遗器、未拥有的角色、空方案、无内容或含无效遗器的更新，以及没有任何改动的更新；改名生效。新增、改名、删除各自独立触发保存，并通过读回 SQLite 验证，不依赖其他操作顺带标脏。

### 队伍

- 按编号补齐普通队伍 `0..8`（包括缺编号或额外队伍先插入的旧存档）；下发的 `index` 与槽位编号一致，额外队伍保留。当前队伍指向空槽时，改用编号最小的非空普通队伍。
- 收藏：`MarkPresetLineupCsReq` 以 `SetTeamFavourite` 回包（4.6 为 cmd `773`，4.7 请求/响应为 `762/780`，4.8 为 cmd `721`）并保存常用标记。合法修改会持久化；额外队伍和普通队伍以外的编号返回 `RetLineupNotExist`。
- 试用角色虚拟队伍：移除最后一名试用角色时拆除虚拟队伍、恢复玩家自己的队伍，并按 `ExtraLineupDestroyNotify → SyncLineupNotify` 的顺序通知客户端。

### 任务与教程

- 任务对话：开启任务系统的玩家在当前追踪主线唯一的 Talk 完成门（`1010202/101020206`）所在楼层发送 `FinishTalkMissionCsReq{talk_str:"0"}` 时只回 ACK，不完成任何任务；客户端上报自己的对话串后，该子任务照常完成。
- 克里珀堡主线过图：使用真实 `FinishTalkMissionCsReq` 和内存 KCP 推进 `101020102 → 101020103`（进门）和 `101020104 → 101020105`（出门）。接取后续任务时，任务脚本可以嵌套传送并完成 EnterFloor 门；聚合通知按发送时的实际状态和进度更新，已发送 Finish 的门不会随后被旧的 Doing 快照覆盖。对照官服 4.6 seq `20633–20654`：出门后停在行政区 `101010102 / 10101001`，接取后续 `101020106`，重复对话只回 ACK，隐藏表演任务 `101020114` 完成后仍在行政区。
- 教程可关闭判定：触发条件含 `OnMazeMainPage` 的自由探索弹窗（如 `3006 → 1000511`）要求目标任务已完成，目标仅进行中时不可关闭；战斗内教程（如 `1001 → 1000101`）仍接受进行中或已完成。`TutorialFinish` 递归时按目标教程自身的触发条件判定严格性。
- 主线开始条件：`AcceptMainMissionByCondition` 同时要求 `TakeParam` 与 `BeginParam`。`1010403` 完成后、开拓等级为 11 时，`1010502` 只记为 `Prepared`（任务列表显示锁定，不启动子任务），经验发放升到 13 级后自动接取。空的或为 `Auto` 的 `BeginParam` 不构成限制。

### 模拟宇宙（经典 Rogue）

- 兼容：`MapEntranceLD.json` 已纳入入口资源；经典 Rogue 的 904 地图可由站点房间池完整生成；ChessRogue 在开始包省略骰面分支时选择完整的默认分支；RogueMagic 查询包含非空区域和必需的嵌套信息；没有存档时差分宇宙大厅入口和徽标默认开启。
- 房间出口：锚点组的 `PROP_ROGUE_DOOR` 携带指向下一房间的 `rogue_game_info{room_id, MAJKFIMPOOF}`。战斗房间以 Closed 加载并忽略已存的道具状态。祝福待选时不开门；经真实 `HandleRogueCommonPendingActionCsReq` 选择后，在响应之前下发 Open 刷新。没有祝福可选的战斗胜利直接开门。开门状态不写入楼层道具存档。

### 存档兼容

- `LineupInfo.IsFavourite` 追加在 MemoryPack 原有的五个成员之后。使用独立的旧五成员契约验证旧存档可读且默认值为 `false`，并验证 SQLite 往返。之后追加的 `IsVirtual`、`PlaneId`（剧情/Raid 试用的虚拟队伍）同样以截去尾部成员的旧数据验证默认值。加收藏标记之前保存的 `LineupInfo` 仍可反序列化。

## 已知缺口

- 这不是安卓客户端测试，不能据此宣称加载卡死已在实机上消失。密钥不匹配会被明确拒绝；客户端要成功登录仍需配套的公私钥。历史 Base64 账号不会被删除或合并。
- 客户端页面、动画和场景体验需要实机验证，特别是：装扮模型和装备页面；角色与光锥快速升级界面；克里珀堡过图时的任务脚本与加载；客户端穿过模拟宇宙教学屏障、碰撞以及结算界面和自动退出请求；图鉴界面与任务交互；进入模拟宇宙战斗时的黑屏是否消失；收容舱段怪物袭击后剧情视角的恢复；视频播放；头像框及其展示开关；各活动界面。
- 克里珀堡、收容舱段和试用主角相关的修复，更新服务端后重新登录重试即可，不需要清空存档。
- 全服聊天的 Discord Webhook 在回归中不发出真实请求。
- 差分宇宙的房间以清除场景内怪物的方式结算，不经过真实战斗。
- 挑战、头像框、ActivityBangboo 和 RealityShow 的检查都只在服务端进行，不能替代客户端实机验证。
